# النشر — خطوة بخطوة (ينشره صاحب المشروع بنفسه)

> هذا المستودع **ما نُشر ولا سُجّل في أي خدمة** من داخل جلسات التطوير. كل ما تحت خطوات تسويها أنت.
> المنتج يشتغل **كاملًا بدون أي متغير بيئة**؛ المتغيرات كلها اختيارية.

## 0. قبل النشر (5 دقائق)

```bash
npm ci
npm run lint && npm run typecheck && npm run validate:data && npm test && npm run build
```

كلها لازم تمر. (نفس الشي يشغّله CI تلقائيًا على كل push: `.github/workflows/ci.yml`، ومعه اختبارات e2e على Pixel 7 وديسكتوب مع axe.)

## 1. الخيار أ: Vercel (الأبسط — 10 دقائق)

1. ادخل [vercel.com](https://vercel.com) بحساب GitHub ← **Add New… → Project** ← اختر مستودع `dalil-alalab`.
2. Framework: **Next.js** (يكتشفه تلقائيًا). أمر البناء: `npm run build` (الافتراضي). Node: **22** (ملف `.nvmrc` موجود؛ تأكد إن إعداد المشروع 22.x).
3. **Environment Variables** (كلها اختيارية — انظر الجدول تحت). أهمها `NEXT_PUBLIC_SITE_URL`.
4. **Deploy**. بعدها افتح الرابط من جوالك وجرّب الرحلة كاملة (قائمة الإطلاق تحت).
5. اربط نطاقك (Settings → Domains). HTTPS تلقائي (مطلوب للـPWA).

> نظام ملفات Vercel للقراءة فقط: لا شي يُكتب على القرص في الإنتاج (طلبات الإضافة والأحداث تروح لـSupabase لو مفعّل، وإلا تُعطَّل بهدوء **ويختفي زر «اطلب إضافته»** عشان ما نوعد بشي ما ينحفظ).

## 2. الخيار ب: Docker على أي خادم

```bash
docker build -t dalil-alalab .
docker run -d --name dalil -p 3000:3000 --env-file .env.local dalil-alalab
```

ضع الخادم خلف HTTPS (Caddy أو Nginx). الصورة فيها `NODE_ENV=production` ورؤوس الأمان (CSP، HSTS، …) تجي من `next.config.ts`.

## 3. الخيار ج: Node مباشرة

```bash
npm ci && npm run build && PORT=3000 npm run start
```

## متغيرات البيئة (كلها اختيارية)

| المتغير                                                                           | متى تحتاجه                                  | ملاحظة                                                                                              |
| --------------------------------------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SITE_URL`                                                            | دائمًا بعد النشر                            | رابط الموقع النهائي (للـQR في الاتفاق المطبوع، وsitemap، وOG).                                      |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`                                               | لو تبي تحفظ الأحداث المجهولة وطلبات الإضافة | المفتاح العام insert فقط (RLS). بدونهما: تعطيل هادئ ولا زر «اطلب إضافته».                           |
| `SUPABASE_SERVICE_ROLE_KEY`                                                       | لو تبي `/about/impact` تعرض الأرقام الفعلية | **server-only**، لا يصل للمتصفح. يقرأ العرضين المجمّعين فقط (`impact_summary`, `feedback_summary`). |
| `ENABLE_AI_CARDS`, `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `MAX_AI_CARDS_PER_DAY` | البطاقات الآلية لعنوان غير موجود            | مدفوعة؛ اتركها مطفأة إلا لو تبيها.                                                                  |

## Supabase (اختياري — 10 دقائق)

1. مشروع جديد (أقرب منطقة). SQL Editor ← شغّل `supabase/migrations/0001_init.sql` ثم `0002_feedback_summary.sql`.
2. Settings → API: انسخ `URL` و`anon` و`service_role` إلى متغيرات البيئة.
3. تحقق: افتح الموقع، وافق على الأحداث المجهولة، كمّل اتفاق، ثم `select * from impact_summary;` — وافتح `/about/impact`.

## قائمة الإطلاق (افحصها على جوالك بعد النشر)

- [ ] `https://<الموقع>/` تفتح، وبحث «أمونق أس» + عمر 10 يوصل لبطاقة فيها «الصورة باختصار».
- [ ] «اضبط» → تبويب iPhone يعرض خطوات باقتباس من دليل Apple، و«سويتها» تنحفظ بعد إعادة التحميل.
- [ ] «اتفق» كامل حتى صفحة الاتفاق، والطباعة تطلع صفحة A4 وحدة، والـQR يفتح بطاقة العنوان (يحتاج `NEXT_PUBLIC_SITE_URL`).
- [ ] شريط الخصوصية يظهر مرة، و«لا، شكرًا» ما يرسل أي طلب (افتح أدوات المطور → Network: لا `/api/events`).
- [ ] `/privacy` → «امسح كل بياناتي» يشتغل.
- [ ] الإضافة للشاشة الرئيسية (PWA) تشتغل، وبطاقة فُتحت قبل تشتغل بدون إنترنت.
- [ ] `https://<الموقع>/robots.txt` و`/sitemap.xml` و`/og.png` تفتح (شارك الرابط في واتساب لنفسك وشوف المعاينة).
- [ ] Lighthouse على الجوال ≥ 90 أداء و100 وصولية (المرجع المحلي في `AUDIT.md`).
- [ ] جولة بقارئ الشاشة على جوالك (TalkBack في أندرويد أو VoiceOver في آيفون): البحث ← «اعرف» ← فتح نقطة ← «اضبط» ← «سويتها». أي شي ما ينقرأ بوضوح سجّله كـissue.
- [ ] إذا فعّلت Supabase: `/about/impact` تعرض الأرقام (وإلا «لم يُقَس بعد» — وهذا صادق).

## بعد النشر — ترفع الدرجة بنفسك

1. **المراجعة البشرية للبيانات (ساعة إلى ساعتين):** `npm run review:data` يعرض كل قيمة آلية مع مصدرها واقتباسها، وتقرر صح/غلط. بعدها `npm run validate:data && npm test` ثم push؛ الشارات تتحول لـ«راجعها إنسان» تلقائيًا.
2. **تحديث المصادر دوريًا (شهريًا):** `npm run fetch:official && npm run apply:official` — يمسح أي قيمة ما عادت في صفحتها ويضيف الجديد (تقرير: `research/official-report.md`). نفس الشي للأجهزة: `fetch:guides` ثم `apply:guides`.
3. **قياس الأثر المتحقق:** خطة التجربة مع الأسر في `docs/PILOT.md`؛ الأرقام تظهر في `/about/impact`.
